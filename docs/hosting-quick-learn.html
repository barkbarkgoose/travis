Quick-Learn Architecture Guide

Namecheap shared hosting

How this Django + Vue application fits into cPanel's constrained hosting model—and how to deploy, restart, protect, and back it up without pretending it is a VPS.

1. The 10-Second Anchor

One managed Python process serves the entire app.

On Namecheap shared hosting, Apache and Phusion Passenger start Django for you. Django then serves the API, admin, and already-built Vue site from the same domain.

Category & core job: a shared-hosting deployment that adapts a full-stack app to cPanel's Python App environment without requiring nginx, gunicorn, root access, or a separate frontend host.

2. The Conceptual Ladder

Build the right mental model first

1
Baseline: a web app needs an HTTP entry point.

On a VPS, you commonly arrange nginx/Caddy → gunicorn → Django, then add a frontend server.

2
Friction: cPanel does not give you those controls.

No root, no systemd, and no custom reverse proxy. Passenger owns the Python process lifecycle.

3
Shift: package the frontend with the backend.

Build Vue into frontend/dist; Django/WhiteNoise serves its files while the SPA helper returns its index.html for browser routes.

4
Configure the app cPanel will actually run.

Use cPanel's virtualenv and keychain values—not the local uv environment—because Passenger can only import packages installed there.

5
Mental takeaway: one origin, one lifecycle owner.

Passenger runs Django; Django owns API/admin/SPA; cPanel owns the outer server and many security controls.

4. The Cast of Characters

The small set of moving parts worth remembering

cPanel Python App

Creates the environment Passenger uses and maps the domain to the application root.

  • Owns: venv, app settings, persistent environment variables.
  • Interface: Setup Python App UI.
  • Doesn't touch: source build or app data setup.

passenger_wsgi.py

The entry file Passenger imports to reach Django.

  • Owns: WSGI entry and production default.
  • Interface: application.
  • Doesn't touch: frontend compilation.

Keychain

Stores encrypted production configuration outside source control.

  • Owns: SECRET_KEY, hosts, proxy setting.
  • Interface: python -m keychain set.
  • Doesn't touch: Passenger's virtualenv.

WhiteNoise + SPA helper

Serves frontend assets and allows Vue Router URLs to load.

  • Owns: frontend/dist, SPA fallback.
  • Interface: Django settings/middleware.
  • Doesn't touch: Django admin's collected static input.

deploy.sh

Repeats the backend deployment sequence after a pull.

  • Owns: install, migrate, collectstatic, restart.
  • Interface: ./deploy.sh [--build-frontend].
  • Doesn't touch: local builds unless asked.

Backups

Independent, encrypted, off-account copies of the evidence and configuration.

  • Owns: recovery from account or disk loss.
  • Interface: cPanel backups / cron / remote storage.
  • Doesn't touch: retention decisions—keep records until resolved.
5. Lifecycle Walkthrough

Follow one visitor request after a successful deploy

Visitoropens a Vue route
→
Apacheterminates HTTPS
→
Passengerhands request to Django
→
SPA fallbackreturns dist/index.html
→
Vuecalls same-origin API
  1. Trigger: a relative opens https://yourdomain.com/visit. Apache has a valid AutoSSL certificate and accepts HTTPS.
  2. Handoff: Apache passes the request to the Passenger-managed WSGI application in backend/passenger_wsgi.py.
  3. Route decision: Django sees that /visit is a client-side route and the SPA code returns frontend/dist/index.html.
  4. Asset delivery: WhiteNoise/Django delivers the built JavaScript and CSS from frontend/dist. This is separate from collectstatic, which covers Django's own admin/DRF assets.
  5. API call: Vue's compiled VITE_API_URL points to the real HTTPS domain, so its API request returns to the same Django app without CORS.
  6. Persistent state: Django reads/writes SQLite and media on the hosting account. Passenger stays available until cPanel restarts it or a deploy touches tmp/restart.txt.
6. The 60-Second Hands-On Spark

Verify the three conditions that make production work

After activating the exact virtualenv command cPanel displayed, run this in ~/travis-recovery/backend. Replace the placeholder host before setting it.

# Confirm Passenger's environment can import the app dependencies
python -c "import django; print(django.get_version())"

# Confirm the two production values that prevent startup and HTTPS problems
python -m keychain set "ALLOWED_HOSTS=yourdomain.com,www.yourdomain.com"
python -m keychain set "TRUST_PROXY_SSL_HEADER=0"

# Ask Passenger to reload, then open https://yourdomain.com
mkdir -p tmp && touch tmp/restart.txt
⚠️ This is not a local command sequence. Run it only in the cPanel-created virtualenv. Using local uv or another Python environment installs packages Passenger cannot see.
7. Field Guide & Sharp Edges

The failures to recognize quickly

⚠️ Redirect loop: On this cPanel setup, set TRUST_PROXY_SSL_HEADER=0. Django must not trust a proxy HTTPS header that Apache generally does not supply here. Set it, then touch tmp/restart.txt.
⚠️ Frontend environment values are compiled, not live: set VITE_API_URL=https://yourdomain.com in frontend/.env.production before pnpm build. An unset build defaults to localhost, sending visitors' browsers to the wrong place.
⚠️ The master key is irreplaceable: keychain.key decrypts keychain.json. Back it up separately, off the server. Losing the account and this key means losing readable secrets.
💡 Deployment blueprint: build Vue locally → upload dist/ with rsync --delete → SSH in and git pull → run ./deploy.sh. Use --build-frontend only when Node/pnpm is available and adequately resourced on the server.

First-deploy checklist

  • DNS points at the Namecheap hosting account; SSH works.
  • Python App uses Python 3.10+ and root travis-recovery/backend.
  • cPanel environment contains DJANGO_ENV=production.
  • Dependencies are installed using cPanel's activated pip.
  • Keychain has SECRET_KEY, real ALLOWED_HOSTS, and TRUST_PROXY_SSL_HEADER=0.
  • keychain.key is backed up away from the server.
  • Built frontend/dist/index.html is on the server with the real API URL embedded.
  • migrate, collectstatic, and bootstrap_family ran.
  • Passenger restarted; HTTPS and AutoSSL are confirmed.
  • At least one real iPhone photo passes the full cutover test.

When shared hosting fits—and when it does not

Good fit
  • One modest app and one origin.
  • You can accept cPanel's server/security boundaries.
  • SQLite and plan-level storage quota are sufficient.
  • You build the frontend locally.
Move toward a VPS when
  • You need firewall, fail2ban, root, or custom reverse proxy behavior.
  • You need an independent process manager or more predictable resources.
  • Storage/upload volume approaches your shared quota.
  • You need database or infrastructure choices unavailable in cPanel.

Backup and storage rules

Keep an encrypted off-server copy, retain it until the case is resolved, and perform a restore drill before relying on it. Photo storage grows quickly: 5 visitors/day × 6 photos × 5 MB is about 4.5 GB/month; originals plus display copy and thumbnail use roughly 1.3× original size.

cd ~/travis-recovery/backend && tar czf - db.sqlite3 media/ keychain.json | \
  gpg --batch --yes --passphrase-file ~/.backup-passphrase -c -o \
  ~/backups/travis-recovery-$(date +\%Y\%m\%d).tar.gz.gpg
